# Client — Chatter Flutter App

Flutter application targeting **Android** and **Windows** from a single
codebase. Uses **Material 3**, responsive layouts, **Riverpod** for state,
**GoRouter** for navigation, and will use **Dio** (HTTP), **WebSocket**,
secure storage and SQLite for offline caching.

## Structure

```
client/
├── lib/
│   ├── main.dart
│   ├── app/
│   │   ├── app.dart            # root ChatterApp (Riverpod + theme + router)
│   │   └── router/             # GoRouter configuration
│   ├── core/
│   │   ├── constants/          # app branding + API endpoints
│   │   ├── providers/          # global providers (theme, ...)
│   │   ├── theme/              # light/dark theming
│   │   └── widgets/            # shared widgets (EmptyState, ...)
│   ├── shell/                  # responsive app shell
│   └── features/               # auth, chat, friends, notifications, profile, settings
└── test/                       # widget + unit tests
```

The app shell is **responsive**: on wide screens (Windows desktop) a left
`NavigationRail` sidebar is used; on narrow screens (Android) a bottom
`NavigationBar` is used. Screens are shared — only the chrome adapts.

## Setup

### Prerequisites

- Flutter SDK 3.x
- For **Windows**: Visual Studio 2022 with the "Desktop development with C++"
  workload enabled.
- For **Android**: Android Studio / Android SDK and JDK 17.

### 1. Generate platform folders

The `android/` and `windows/` platform folders are generated by Flutter and are
not committed. From the `client/` directory:

```bash
flutter create .
```

This keeps the runner code and Gradle/CMake files in sync with your Flutter
version. The `lib/` source is preserved.

### 2. Install dependencies

```bash
cd client
flutter pub get
```

### 3. Configure the backend URL

Edit `lib/core/constants/app_constants.dart`, or override at build time:

```bash
flutter run -d windows --dart-define=API_BASE_URL=http://localhost:8080
flutter run -d <android-device> --dart-define=API_BASE_URL=http://<your-lan-ip>:8080
```

> The Android emulator reaches the host machine at `10.0.2.2`; a real device
> needs your machine's LAN IP. Windows desktop uses `localhost`.

### 4. Run

```bash
flutter run -d windows
flutter run -d <android-device-or-emulator>
```

### 5. Tests / analysis

```bash
flutter analyze
flutter test
```

## Theme

Brand colors and light/dark themes are centralized in
`lib/core/theme/app_theme.dart` and `lib/core/constants/app_constants.dart`
so the app can be re-branded by editing a couple of files.

## Builds

```bash
flutter build apk --debug
flutter build apk --release
flutter build windows --release
```
